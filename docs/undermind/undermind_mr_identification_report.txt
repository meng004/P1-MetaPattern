Summary
The literature shows that essentially all prior work on metamorphic relation (MR) identification is expertdriven, taxonomy/patternbased, or search/ML/modelbased—with no existing framework systematically deriving MR classes and boundaries from a
programfamily operator algebra—so NOETHER [1] appears to be the first to make operatoralgebraic derivation, operatorblock
coverage, and traceable algebraic origin explicit evidence dimensions distinct from faultdetection effectiveness.

Overall Landscape: How MR Identification Has Been Treated
Dominant paradigms: expert, taxonomy, search/ML, modelbased
Across surveys and primary papers, MR identification is consistently framed along three main lines, plus a smaller “modelbased”
strand:
• Expert/manual MRs, often informed by domain knowledge, physics, specs, or code inspection.
• Nuclear and CRAM work defines hierarchical MR models (physics/algorithm/code layers) and derives MRs from physical
equations and numerical schemes [18,56].
• Many domain studies in AI/ML and scientific computing also handcraft MRs; surveys emphasize this as the historical norm
[5,6,54].
• Taxonomy / patternbased identification, where MRs are catalogued and reused as patterns:
• METRIC / METRIC+ / CCML: categorychoice frameworks where testers select MR categories based on input/output
domain properties; METRIC+ adds outputdomain structure and CCML/CCMT provide a general MR description language
and tool support [8,10,13].
• MR patterns (MRPs, MRIPs/MROPs, MROPs) for querybased systems and REST APIs, often inspired by relational
algebra but used as reusable templates (filtering, ordering, subset, disjoint, etc.) [12,15,19,21,37,39].
• General MR pattern frameworks and “family trees” of MRPs for MT, metamorphic exploration, and robustness [14,21].
• LLM testing catalogues (e.g., 191 NLP MRs for LLMORPH) are also taxonomystyle collections [48].
• Search / ML / miningbased MR discovery, operating over syntactic templates or feature spaces:
• Searchbased numeric MR inference: polynomial MRs [25], AutoMR with PSO+SVD [26], GEPbased symbolic MR
inference [27,28].
• Genetic programming to generate executable MRs or assertionstyle MRs (GenMorph, GAssertMRs) [31,32].
• Composite MR search via genetic algorithms and empirical study of composite depth [29,30].
• Executionmining: KABU’s dynamic inference of “likely” MPs from executions [23]; MRScout’s mining of MRencoded test
cases [38]; MetBench as a benchmark corpus of 924 numericalexpression MRs [53].
• ML prediction of MR applicability from program structure and documentation: graphkernel and RBFbased MR predictors [46,47,50,52], textmining (MRpredT) [45], and lightweight codemetric predictors [55].
• NLP/documentationbased extraction: MeMo infers equivalence MRs from Javadoc [40].
• Modelbased (but nonalgebraic) MR generation:
• Causal DAGs define expected input–output causal structures from which MRs and tests are systematically generated
[34].
• Objectprotocol abstraction (MemoRIA) derives methodequivalence MRs from protocol automata plus fuzzing and
SATbased validation [33].
• Tabularexpression specs yield MRs from the structure of tabular requirements [16].

Role of Algebra, Invariants, and Symmetries in Existing MT Work
Algebraic terminology is descriptive, not a generative operator calculus
Several strands mention algebraic notions—associativity, commutativity, symmetry, monotonicity, conservation—but use them as
labels or inspiration rather than as a structured operator algebra:
• Surveys catalog “algebraic” MR types (e.g., additive, multiplicative, periodic, subset) and contrast them with invariants and
other relations, but do not define a formal algebra whose laws generate MR families [5,6].
• Querybased MRPs explicitly “resort to relational algebra” to motivate patterns for filtering, projection, join, ordering, etc.
[12,15,19]. However:
• Relational algebra operators serve as a vocabulary to describe queries and patterns, not as a formally closed algebra
with equivalence rules that are used to derive MR classes and boundaries.
• There is no explicit algebraic analysis of where these patterns break (e.g., under nonset semantics, stateful queries), nor
any operatorblock coverage metric over relational operators.
• Numeric and scientific MRs routinely come from algebraic identities, monotonicity, conservation laws (probability sums to 1,
sortedness preserved, etc.), especially in nuclear and scientific codes [18,56,54]. But:
• These laws are cited as domain equations or “natural properties,” not organized into a programfamily operator algebra
with stated composition rules and equivalence relations.
• Boundaries (e.g., breakdown of numerical approximations) are discussed as domain caveats rather than as formal
algebraic scope conditions.
• Inputpattern decomposition provides algebraicflavored structure on the input side: any input pattern can be expressed as a
combination of basic patterns in scientific computing [17]. Yet:
• This concerns only the input pattern space, not the semantics of operators composing the program under test.
• It does not derive MR classes as consequences of operator equivalences or monotone operators over the program family.
In short, algebraic properties and symmetries appear as informal sources of MR ideas or as part of MR taxonomies, but there is
no prior systematic treatment that:
1. Defines a set of primitive operators over a program family.
1. States composition/equivalence laws over those operators.
1. Systematically derives MR classes or MetaPatterns from those laws, with explicit validity conditions and boundary characterization.

Treatment of MR Origin, Boundaries, and Coverage in Prior Work
MR origin/provenance is mostly informal or taxonomic
• Manual/domaindriven origin dominates:
• Surveys and case studies repeatedly emphasize that MRs rely heavily on domain expertise and understanding of the
SUT [5,6,54].
• Nuclear software work traces MRs to physics models, numerical algorithms, or code level assumptions, grouped
into hierarchical layers (MRHM) [18,56]. This is explicit provenance but at a semantic layer level, not in terms of primitive
operators and algebraic laws.
• Taxonomy/pattern provenance:
• METRIC/METRIC+/CCML tie MRs to input/output domain category choices and MR patterns; origin is “selected
pattern/category for this spec frame” [8,10,13].
• MRP/MROP work for QBS, REST, and model transformations traces concrete MRs to pattern catalogues, MRIPs/MROPs, or mined generic trace patterns [12,14,15,19,37,39].
• Search/ML provenance is mostly algorithmic:
• Searchbased and ML methods attribute MRs to the search, optimization, or learning algorithm (e.g., PSO, GP, GEP,
graphkernel classifier) [23,25,26,27,29,30,31,32,33,35,36,38,40,45,46,47,50,52,55].

• LLMbased origin is semanticbutopaque:

No prior work in this corpus attaches every MR or MR class to named operator blocks and explicit algebraic laws governing

Boundaries and validity conditions are rarely formalized
• Most methods implicitly constrain scope by:
• Limiting to numeric programs or certain data types [25,26,31,32,35,36].
• Constraining to equivalence or polynomial MRs, or to predefined MR types [25,26,40,46,47,52].
• Focusing on specific domains (QBS, REST, CPS, nuclear) [12,15,19,32,56].
• Some works explicitly flag “likely” MRs:
• KABU and Troya et al. call their inferred relations “likely metamorphic properties/relations” because they reflect observed
executions and may encode implementation bugs [23,37].
• Nuclear work distinguishes static (theorybased) vs dynamic (datafitted) “likely” MRs and notes that the latter lack
theoretical proof [18].
• Model misspecification is acknowledged but not algebraically framed:
• Causal MT notes that MRs derived from misspecified DAGs can be unsound, and studies robustness to such misspecification [34].
Even in the most structured work, boundaries are expressed as domain or model caveats, not as precise algebraic scope
preconditions and outofscope strata where particular operator laws cease to hold.

Coverage metrics are almost never operatorlevel
Coverage in MT work is overwhelmingly defined at the test or code level:
• Code coverage and mutation score (fault detection effectiveness) are the standard metrics for MR sets
[10,18,22,26,31,32,38,41,48].
• Some work counts the number/diversity of MRs or the proportion of MR types covered (e.g., how many patterns instantiated)
[19,37,48].
• Fu et al. define MT adequacy criteria and a measurement framework, but still within the space of test inputs, MR usage,
and code coverage, not operator coverage [7].
No prior paper defines coverage over an operator algebra, such as:
• Which primitive operators or combinations are exercised by a given MR set.
• Which equivalence/transform rules in an operator calculus have corresponding MRs.
• How completely the operator blocks of a program family are covered.
This is precisely the dimension that NOETHER introduces as “operatorblock coverage” [1].

Where NOETHER Fits and What It Contributes
NOETHER’s operatoralgebraic framework
NOETHER [1] is unique in this corpus in that it:
• Assumes an upstream operator algebra for a program family, decomposed into eight explicitly named blocks (symmetry,
order, selfadjoint, timereversal, limit, qualitativedynamics, methodcomparison, relationalequivalence), each with documented
scope preconditions.
• Defines a constructive MetaPattern calculus:
• MetaPatterns are equivalence classes over MRs.
• The CONSTRUCTMP algorithm mechanically derives a set of MetaPatterns from the operator algebra and proves:
• Closure of MetaPatterns under a Translate operator (Theorem 1).
• Polynomialtime decidability of MetaPattern generation under a finite generating set (Theorem 2).
• Emphasizes traceable algebraic origin:

How this differs from and complements existing MR identification methods
Relative to the established paradigms, NOETHER:
• Is not a replacement for expert, taxonomy, search/ML, or LLMbased MR identification; instead it provides a new orthogonal
axis:
• Expert/taxonomy methods (METRIC, MRPs, nuclear MR hierarchies) can be seen as empirical catalogues of useful
MRs and patterns. NOETHER offers a way to reground such catalogues in operator algebras, making explicit which
operator laws generate which pattern families and where they fail.
• Search/ML/GP/GEP methods optimize over syntactic or template search spaces; they are powerful at discovering
effective MRs but have weak structural provenance. NOETHER can provide algebraically justified search spaces and
priors, or be used to assess whether discovered MRs fall within expected operatoralgebraic classes or probe neglected
operator blocks.
• Modelbased and causal approaches structure MRs around graphs or abstractions; NOETHER structures them
around compositional operators, giving a different, complementary notion of structure.
• LLMbased methods treat MR identification as semantic text/code understanding; their outputs could be constrained,
checked, or categorised by an operator algebra, enabling LLM+algebra hybrid pipelines (e.g., LLM proposes candidate
transformations; NOETHER checks if they correspond to known operator blocks and whether scope conditions hold).
• Introduces new evidence dimensions for MR sets:
• Prior work overwhelmingly equates MR quality with faultdetection effectiveness, sometimes supplemented by code/mutant coverage and MR count.
• NOETHER foregrounds:
• Algebraic provenance (mapping each MR to operator laws).
• Boundary characterization (documented conditions under which each MR class is sound/unsound).
• Operatorblock coverage (which parts of the operator algebra are exercised by the MR set).
• This allows MR methodologies to be argued as complementary rather than purely competitive on fault detection.
Given the surveyed literature, it is accurate and defensible to position NOETHER as:
• The first operatoralgebraic MR identification framework in the MT literature;
• A method whose main contribution is systematic derivation of MR classes and boundaries

Comparative Treatment of MR Origin, Boundaries, and Coverage
MR origin/provenance
• Explicit provenance as “domain layer”
• Nuclear and CRAM MRHM works [18,56] explicitly separate physics model MRs, algorithm MRs, and code MRs, and
distinguish static vs dynamic MR discovery [18].
• MetBench [53] documents MR sources (open source, academic, industrial software).
• Patternlevel provenance
• MRP/MROP work [12,14,15,19,21,37,39] traces MRs to general query/REST semantics or prior pattern catalogues.
• METRIC/METRIC+ / CCML [8,10,13] trace MRs to input/output domain characteristics and categorychoice decisions.
• Search/ML provenance
• Searchbased and ML approaches attribute MRs to their underlying search or training process (e.g., PSO search, GP, GEP,
causalgraph models) [23,25,26,27,29,30,31,32,33,35,36,38,40,45,46,47,49,50,52,55].
• Provenance is algorithmic (“found by AutoMR/GenMorph”) but not semantic; they do not usually maintain a decomposed
trail back to a primitive operator law.
• NOETHER’s operatoralgebraic provenance
• NOETHER defines an empirically curated operatoralgebra decomposition into eight blocks and derives MetaPatterns
algorithmically, tying each to its generating operator block(s) [1].
• This makes provenance structural: each MetaPattern and MR instance can be linked to specific algebraic laws and
operatorblock compositions [1].

Boundaries / validity conditions
• Many works use informal or local boundaries:
• Limited to numeric input/output or specific template families [25,26,31,32,35,36].
• Applicability to certain domains (query systems, model transformations, scientific computing) [12,15,19,37].
• “Likely” MRs inferred from data are explicitly warned as not universally valid [23,37].
• Nuclear software papers [18,56] make physics and algorithm limits explicit (e.g., model assumptions, numerical schemes),
but still do not phrase them as algebraic boundaries over operators.
• Causalgraph work [34] discusses misspecification of causal models and its impact on MR soundness, again as modelvalidity
boundaries, not algebraic ones.
• NOETHER uniquely:
• Defines outofscope strata for its operator algebra (where particular algebraic laws do not hold, e.g., floatingpoint
nonassociativity, broken symmetries) [1].
• Demonstrates falsifiable predictions about where its operatoralgebraic patterns will fail (e.g., L*blindness on homogeneitypreserving mutators), and documents counterexamples that falsify an “absolute completeness” conjecture (APWR) [1].
• Treats boundary characterization as a central, falsifiable component of the contribution, not just incidental domain
caveats.

Coverage definitions
• Standard MT coverage metrics
• Most works evaluate coverage in terms of code coverage and mutation (fault) coverage, sometimes line/branch
coverage [10,18,22,26,31,32,38,41,48].
• Some address MR coverage merely as the number or diversity of MRs instantiated [19,37,53].
• Test adequacy criteria for MT
• Fu et al. [7] focus specifically on test adequacy for MT, rigorously defining adequacy criteria and measurement for MT
regimes. Their metrics consider MR identification and source inputs as key elements but still operate at the test/MR level,
not at an operatorblock algebra level.
• Behavioral/abstraction coverage
• MARS [44] uses behavioral coverage under abstraction/refinement; causalMT [34] speaks of exercising structural causal
relations; MemoRIA [33] aims to cover more behaviors via objectprotocol abstraction.

• It does not primarily compete on faultdetection effectiveness (though it evaluates against a GP baseline);
• Instead, it contributes:
• an operatoralgebraic generative framework for MR/MetaPattern classes,
• explicit, falsifiable boundary characterizations, and

Timeline
Chronological Phases in MetamorphicRelation Identification
Phase 0 (pre2013): MT concept established, MR identification largely manual
This phase is mostly summarized retrospectively by later surveys. MRs were:
• Handcrafted by experts from domain knowledge or specifications.
• Often inspired by algebraic laws, invariants, symmetries, and monotonicity, but without an explicit calculus that generates
MR classes.
Segura et al. [5] and Chen et al. [6] document this period as dominated by manual MR derivation, with a few domainspecific
catalogues (e.g., numeric computations, search, ML).

Phase 1 (2013–2016): First automation attempts and foundational surveys
Key developments
1. MLbased MR prediction (programanalysis features)
• Kanewala & Bieman’s line of work [46,47,52] introduces predictive models (graph kernels, code metrics) to decide which
predefined MRs apply to a given program.
• Programs are represented via controlflow graphs; features feed supervised ML classifiers that output MR labels.
• Conceptually: MR identification shifts from purely expertdriven to MLassisted classification over a fixed MR vocabulary.

• MR identification is recognized as central and difficult.

• Search/mining: infer numeric MRs from traces (Zhang et al. [25], Su et al. [23]).

Phase 2 (2017–2019): Patterns, taxonomies, and broader automatic MR generation
Patterns and taxonomies as reusable MR abstractions

• Define MRIPs (input patterns) and MROPs (output patterns), and a catalogue of 24 domainindependent MRs plus

• Operatorlevel coverage: which operator blocks and equivalence rules are exercised by the instantiated MRs.
• Examples:
• Deriving rotationequivariance MRs for equivariant ML from symmetry block operators.
• Systematizing a catalogue for a Boltzmann reactor via methodcomparison and qualitativedynamics blocks.
• Empirical results include:

• A falsifiable prediction of L*blindness on certain mutators that holds inscope.
• Documented counterexamples that falsify an absolutecompleteness conjecture and identify extensions to the

• MRs are grouped into patterns that can be reused across systems.
• Identification becomes: choose patterns + instantiate parameters.
• These taxonomies are descriptive, not generative: they do not arise from an operator calculus; they enumerate what
practitioners found useful.

From pattern reuse to search/MLbased generation
• Phase 1–4 introduce searchbased (PSO, GP, GEP, GA) [25,26,27,29,31,32] and MLbased prediction/mining
[40,45,46,47,52,55,38] methods:
• Search methods work over explicit syntactic templates (polynomials, symbolic expressions, MR expression trees,
assertion templates).
• ML methods map structural or textual features to MR labels.
• In all these, the search space is defined syntactically or via patterns; operators are “language constructs” (AST nodes,
numeric operations), not semantic operators with a defined algebra.

Model and structuredriven MR generation (but not algebraic)
• Relational algebra is used as a reference language for MRPs in QBSs [12,19], but there is no formal algebraic closure or
boundary analysis.
• Input pattern structural models [17] provide decomposition theorems for input patterns but do not extend to full operator
algebras or MR class boundaries.
• Causal graphs [34] and abstraction/refinement loops [44] add formal structure, but in terms of causality and abstraction,
not algebraic operator laws.

From automation effectiveness to structural adequacy and coverage
• Most work evaluates MRs via fault detection, mutant kill rate, and code/branch coverage [25,26,31,32,38].
• Adequacy work [7] begins to formalize MT-specific adequacy criteria, but still largely in terms of input/MR usage and code
coverage, not operatorblock coverage.
• NOETHER [1] introduces operatorblock coverage and algebraic structural adequacy as explicit metrics, decoupling:
• “How many faults are detected?” from
• “Which operator equivalence laws and blocks of the operator algebra are exercised?”

From Adjacent Structures to Operator Algebras: Precursors and Distinctions
Several strands approach algebraic ideas without crossing into a true operatoralgebraic MR derivation:
• Relational algebra as inspiration: MR patterns for QBS [12,19] talk about relational algebra, but:
• Operators are used to describe queries, not to build a closed algebra with identities/equivalences that generates
MRs.
• Patterns are still enumerated and validated empirically.
• Structural decompositions of input patterns:
• Yan et al. [17] define classes of basic input patterns and prove that any input pattern decomposes into them, with an
identification algorithm.
• This is algebraic in flavor, but:
• Only targets input patterns, not full input–output operator behavior.

• Tabular expressions and model transformations [16,37,39]:
• Treat specs or traces as structured objects from which MRs can be derived systematically.
• They do not introduce an operator algebra over program transformations; the derived MRs are still pattern instances.
• Causal graphs [34] and abstraction/refinement [44]:

• They are about structural/causal relations, not equivalence laws in an algebra.
None of these efforts:
1. Define a set of primitive operators over a program family, with composition and equivalence laws.
1. Use those laws to systematically derive classes of MRs as consequences of operator equivalences or monotone transformations.
1. Provide explicit boundary characterizations (where the laws fail) and coverage notions over operators/operator blocks.
NOETHER [1] is the first in this corpus to satisfy all three, making the operatoralgebraic dimension orthogonal to:
• Expert/manual MRs (including domaintheory based ones).
• Taxonomy/patternbased reuse.
• Search/ML/LLMbased MR generation from traces, code, or text.

Implications for the Field and NOETHER’s Positioning
Historical narrative
1. Manual era ’ pattern/taxonomy:
• MRs begin as expertinvented semantic constraints, later organized into families and patterns [5,6,12,14,15,21,37].
1. Automation era (search/ML/mining):
• MR identification becomes a search/learning problem over syntactic templates, code graphs, or test artifacts
[23,25,26,31,32,38,40,45,46,47,52,55].
• These methods primarily optimize fault detection and coverage over code/test inputs, not structural adequacy in an
operator space.
1. Structureaware era (patterns + models + LLMs):
• MR identification is enriched with causal models [34], specification languages [13], abstraction/refinement [44], and
LLMdriven synthesis [9,41,42,43,51].
• Formal structure is still pattern, graph, or modelbased, not operatoralgebraic.
1. Operatoralgebraic turn (NOETHER):
• NOETHER [1] brings a compositional operator algebra to the center, with:
• Declared operator blocks and scope preconditions.
• Formal closure and decidability theorems.
• MetaPatterns as equivalence classes over MRs with traceable algebraic origin, documented boundaries, and
operatorblock coverage.
• It treats MR identification as constructing and exploring the operator algebra underlying a program family, rather than
as:
• Enumerating MR patterns.
• Searching over syntactic templates.
• Predicting MR labels via ML.

Future directions suggested by the trajectory
• Integration of operator algebras with existing methods:
• Pattern/taxonomy work could be regrounded in an operator algebra (derive MRPs/MROPs as algebraic classes) and
given explicit boundary conditions.
• Searchbased generators (GenMorph, AutoMR, GEP) could restrict or guide their search to algebraically justified
regions of the MR space.
