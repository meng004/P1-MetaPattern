## Reviewer 2 视角的最严苛审稿意见

### Dimension 1 — 方法论（控制变量、可重现性、对照可比性、协议完整性）

#### 1.1 Set N MR 的人工推导未做 inter-rater 校验
- **【严重】** §1（C1–C4）和 §6.5–§6.6 主张 Set N 的 30 条 MR 是 NOETHER 算法 *机械* 推导的产物，但实际推导路径是单一作者人工执行 CONSTRUCT-MP 四步过程，论文未报告任何 inter-rater κ。CLAUDE.md §5 P3 已为 LRCA 二评者 κ 留出位置（"工业 Java / C++ port + LRCA 二评者 κ — 未启动"），证实作者本身意识到此漏洞。
  - **证据**：`NOETHER_paper.tex` §6.6（line 1142–1148）"Set~N contains 30 hand-derived NOETHER MRs"；§1 contribution（line 133）"a constructive algorithm for deriving MetaPatterns"；论文全文仅在 line 498 的 18-MR audit 报告 Fleiss κ=0.857（且作者已自承"the three models share substantial pre-training corpora, so κ should be read as agreement among similarly-trained but non-coordinated raters rather than among rigorously independent oracles"）；Set N 主推导无 κ。
  - **TOSEM R2 为什么会 catch**：TOSEM 评审对"机械化"主张的 evidentiary 标准极高。论文以 Theorem 2 论证 *polynomial-time decidability* 表明算法是机械的；但实证产物是人为产出的，构成 method–evidence 不一致。R2 会问："如果 CONSTRUCT-MP 是机械的，为什么 30 条 MR 不能被独立的第二位推导者重现？"
  - **建议缓解**：在 §6.5 / §6.6 / §Threats（construct validity）显式承认 Set N 由单人推导，并为 P3 转化阶段（CLAUDE.md §5）预约二评者 κ；或（更弱版本）声明 Set N 是 *示例性* 推导而非机械产出，将 polynomial-time decidability 与 manual derivation 在文中明确分离。

#### 1.2 Hand-constructed mutation set 的循环验证（construct validity 已部分披露但仍欠彻底）
- **【严重】** §6.6 case study 已诚实标注："The mutation set was constructed to cover one defect category per non-empty block of $\mathcal{A}_{\mathrm{equi}}$" — cat-(iv) 是为 $\rho_{\text{train-rev}}$ 量身定制（line 717，line 760(c)）。但这条 caveat 仅出现在 paragraph 17/19 之后；abstract、§1 contribution C4、§6.6 Table 4（line 700–708）的"5/5 unique-detection"叙述仍是主旋律。
  - **证据**：line 137（C4: "detection-rate direction matches prediction"），line 700（"Detected cat.~(iv) gradient-reversal sign 5/5 0/5 0/5"），line 712（"H2 is consistent with the data at conventional significance: McNemar p=0.016"）。
  - **TOSEM R2 为什么会 catch**：构造-检测的 self-fulfilling design 是 SE 实证研究最常见的方法论瑕疵（Wohlin 2012 §10 explicitly flags this）。"我们设计了一个针对自己 MR 的 mutation；我们的 MR 检测到了这个 mutation"是 tautological 的。论文已承认了 caveat，但 abstract 与 contribution 段落仍以"5/5 unique-detection at McNemar p=0.016"作为主结论，等于 caveat-after-the-fact。
  - **建议缓解**：将 abstract / C4 / §6.6 main result 改写，去掉 detection-rate 的 5/5 / p=0.016 数字，仅保留 §6.6.1 DeepCrime pilot 的 2/5 vs 0/5（n=5, p=1.00）作为 *未受 construct-validity 污染* 的 detection 证据；构造性 mutation 结果下放到 Appendix。p2 论文领域有先例：被 reviewer 否决后 disgrace。

#### 1.3 Set L (LLM-prompt baseline) 的协议未通过任何独立验证
- **【严重】** §6.6 case study 的 Set L 只用 *单次* GPT-4 sample（temperature 0, fixed seed）（line 760(e)）。LLM 输出对 prompt 敏感性是 SE 文献常识；单次采样的 baseline 无法支撑"NOETHER > LLM"的 narrative。
  - **证据**：line 665–666（"five MRs generated by prompting GPT-4 with the task description ..."），line 760(e)（"Set L is a single GPT-4 sample at temperature 0 with a fixed seed; a different LLM, prompt, or temperature would yield different MRs"）。
  - **TOSEM R2 为什么会 catch**：2024–2026 LLM-baseline 公正性已是 SE 顶会 ARS 高频话题。Xu et al. TOSEM 2024（论文已引）正是测量"LLM-generated MRs across multiple ML benchmarks"的多样性。本论文却用 N=1 LLM run 作 baseline，与 Xu 2024 形成讽刺对照。
  - **建议缓解**：将 Set L 扩展到 ≥3 GPT-4 + ≥1 Claude + ≥1 GPT-OSS，per-LLM 独立 5-MR 采样（n≥15），报告"NOETHER vs LLM-fleet"。或在 §Threats 显式声明 Set L 不是 SOTA LLM-baseline，而是 *anecdotal LLM 对照*。

### Dimension 2 — 外部效度（样本代表性、泛化）

#### 2.1 §6.6 SUT 全部来自 MathSignalClass 单一 codebase，无 cross-codebase replication
- **【严重】** §6.6 的 10 个 in-scope SUT 中 9 个属于 `MathSignalClass`（midpoint, exactLog2, isSequence, clamp, signum, gcdSig, lcmSig, hypotSig, powerSig），仅 1 个来自 `ComplexSignal`。`paper_claims_summary.md` 明确这是单一 codebase。原始 23 SUT GenMorph benchmark 中只有这 10 个被选入 NOETHER 评估。
  - **证据**：`NOETHER_paper.tex` line 1124（"Ten SUTs admit at least one non-trivial NOETHER block beyond G: midpoint, exactLog2, isSequence (boolean predicate), clamp, signum, ComplexSignal.add (instance method), gcdSig, lcmSig, hypotSig, powerSig"）；`NOETHER_6_6_summary.md` §4。
  - **TOSEM R2 为什么会 catch**："Selection bias on the SUT pool" 是 TOSEM 实证 SE 投稿的标准否决理由。即便 selection criterion 是 pre-registered 的（确实是，§6.6.2 line 1109–1122 解释 git timestamp chain），从同一 codebase 选 9/10 SUT 仍是 within-codebase replication，不是 cross-codebase。NOETHER 的核心 transferability claim（C4）需要 cross-codebase 证据。
  - **建议缓解**：（a）显式将 §6.6 重命名为"§6.6 single-codebase pilot, n=10"；（b）在 §Threats external validity（line 1546）补一句"All 10 SUTs are mathematical-signal utility functions; cross-codebase replication on Apache Commons Math `linear`, `ode`, `transform` packages is enumerated in PLAN-007 future-work option (b) and remains uncompleted"；（c）至少为 future-work 表加 *cross-codebase replication on ≥2 distinct codebases* 一行。

#### 2.2 §6.6.1 DeepCrime pilot n=5 的样本规模不足以支撑 Hypothesis 1 ninth-block 推论
- **【严重】** §6.6.1 的 5 mutations（cat-v-01..05）中 3 条未被 Set N 检测（cat-v-02 activation change, cat-v-04 bias removal, cat-v-05 weight re-init），论文将此解读为"empirical witness for Remark 6 item (vi) (parameter-distribution out-of-scope class)... motivate a candidate ninth block"（line 757）。然而 3 mutation 不足以建立 *存在新 block* 的归纳：可能仅是 EGNN 5189-参数模型对这些 mutation 鲁棒。
  - **证据**：line 747–757（pilot table + reading），CLAUDE.md C6（"n ≤ 10 的 pilot：abstract 与正文必须明确写 'n=N, underpowered for α=0.05 hypothesis testing'"）。
  - **TOSEM R2 为什么会 catch**：从 3 个 pilot mutation 推论"a candidate ninth block exists"是 over-fitting 到 anecdotal evidence。CLAUDE.md C6 已经禁止用"trends suggest"/"directional evidence"包装 underpowered finding。
  - **建议缓解**：将 §6.6.1 的"empirical witness for ninth block"改为"three under-detected mutations are *consistent with*, but do not establish, the parameter-distribution candidate ninth block of Remark 6 item (vi); a >n=20 mutation panel on >1 architecture is required to establish the block-extension claim"。Remark 6 的 item (vi) 措辞需相应弱化。

#### 2.3 PWR 负 instantiation 用 PWR 自己的 §5 catalogue 当反例 — 自闭环风险
- **【严重】** §6.6.0 的 negative instantiation 选择 PWR core diffusion algebra 作为反例 algebra，然而 §5 instantiation 的 84-MR PWR catalogue 正是用来 *支持* NOETHER 的；两者处于同一物理域。这造成"在我们能讲故事的域里我们 worked；在我们能讲故事的域里我们 *也*被反例了"的微妙叙事，TOSEM R2 会要求在 *NOETHER 未训练过* 的域举反例。
  - **证据**：line 836–991（§6.6.0 PWR 负 instantiation，引用 BellGlasstone1970, LewisMiller1993，与 §5 引用同源）；line 492（self-disclosed circularity caveat for $T^*$ / $\mathcal{T}^*$）。
  - **TOSEM R2 为什么会 catch**：选择反例域的 strategic placement（在已训练好的域内反 *自身的强主张* Theorem 1'）虽然学术诚实，但 R2 会问："为什么 SE(3)-equivariant ML 或 relational query optimisers 域 *没有* 反例？这是因为 NOETHER 真的覆盖了它们，还是因为这两个域是用来支撑 NOETHER 的，反例隐藏在未列出的 corner case 中？"
  - **建议缓解**：（a）补一段"Why we chose PWR rather than ML or DB as the negative-instantiation domain"，解释 PWR 反例的 *engineering essentiality*（regulatory）作为选择动机；（b）添加一句"Whether $\mathcal{A}_{\mathrm{equi}}$ or $\mathcal{A}_{\mathrm{rel}}$ admit analogous Theorem 1' counterexamples is open; we conjecture that the SO(3) Lie-algebra structure forces algebra-induced closure but the boundary remains untested"。

### Dimension 3 — 统计选择偏差（Cherry-picking、多重比较、预注册、HARKing）

#### 3.1 8 个 per-SUT 比较未做 Bonferroni / FDR 校正
- **【致命】** §6.6（line 1373–1378）报告 per-SUT delta（midpoint 0, exactLog2 +4, clamp -3, signum 0, gcdSig +1, hypotSig -2, lcmSig -3, powerSig +1）以及 §6.6.0 提到 "Bonferroni correction for the 10 pairwise tests across 5 sets"（line 770）— 但 §6.6 实际报告的 8 SUT 比较（即 Set N vs Set G per-SUT）从未应用 Bonferroni。pooled McNemar p=0.359（1-min）与 p=0.077（30-min）是单次检验，没有问题；但 per-SUT 8 个 paired 检验的 family-wise error rate 控制完全缺失。
  - **证据**：line 1373（per-SUT delta column 直接报告），line 770（Bonferroni 仅在 *未来 protocol* §6.6.2 H3/H4 中承诺，未在 §6.6 已落地的 per-SUT 比较中执行），`e3b_gp_30min_rerun_results.md` line 22–34（同样无校正）。
  - **TOSEM R2 为什么会 catch**：8 SUT × 2 budgets = 16 paired comparisons 已是 multiple-testing 范畴。Bonferroni 校正后 α/16 ≈ 0.003，意味着任何 SUT 单独"winner"标注都不达校正后显著阈值。论文的 winner 标注（line 1370 "tie / G / +4 N narrow"）暗示 per-SUT 显著性差异，缺乏校正基础。
  - **建议缓解**：（a）在 §6.6 表中删除 winner 列，或将 winner 列重新表述为 "directional only, no per-SUT statistical significance asserted"；（b）将 8 SUT × 2 budgets 的 16 paired 检验做 Holm-Bonferroni 校正；或（c）显式声明 per-SUT 比较是 descriptive，仅 pooled comparison 受统计推论保护。

#### 3.2 §6.6 落地的 H1/H2/H3/H4 中 H3/H4 仍是 protocol，H1 同义反复
- **【严重】** §6.6.2 case study pre-registers H1 + H2；但 H1 由作者承认是"by construction"（line 712: "by construction... it cannot fail unless one of those derivations is itself in error"），等于不可证伪的同义反复。H2 受 §1.2 construct-validity 损害。H3/H4 是 *未来* protocol 而非已执行的 hypothesis test。论文实际只 报告了 H2 的污染版结果。
  - **证据**：line 682（H1 statement），line 685（H2 statement），line 712（H1 self-disclosed by-construction），line 717（H2 construct validity caveat）；§6.6.2 H3/H4（line 771–772）。
  - **TOSEM R2 为什么会 catch**：pre-registration 的 epistemic value 来自 *unfalsifiable hypothesis 的过滤*。H1 是 unfalsifiable（by-construction），H2 受 construct-validity 污染，H3/H4 还没跑。这意味着 §6.6 的"pre-registered hypothesis test"事实上是 0 条受合格 protocol 保护的 hypothesis。
  - **建议缓解**：（a）从 H1/H2 列表中删除 H1（或将其降级为 "structural sanity check, not a falsifiable hypothesis"）；（b）H2 verdict 改写为"H2 is consistent with the data, but the verdict is uninterpretable due to the construct-validity threat documented above; the comparative-evaluation protocol of §6.6.2 H3/H4 is the appropriate next test"。

#### 3.3 Pre-registration anchor 是 timestamp 而非 third-party registry — 部分合规
- **【已知小瑕疵】** §6.6 selection criterion 通过 git timestamp chain pre-register（line 1119–1122 "the auditable proof of pre-registration"），未提交到 OSF / AsPredicted / OpenReview 等第三方 registry。timestamp-anchored pre-registration 在 SE 社区认可度低于跨学科标准（OSF）。
  - **证据**：line 1119（git timestamp chain），`NOETHER_6_6_summary.md` §2（"git timestamp chain... is the auditable proof of pre-registration"）。
  - **TOSEM R2 为什么会 catch**：TOSEM 投稿主体偏向第三方 registry。git timestamp 可被 author 单方修改（rebase, force-push）；reviewer 无法独立验证 timestamp 的不变性。
  - **建议缓解**：投稿时将 `configs/d4j_algebra_rich_criterion.json` 的 SHA-256 commit 到 OSF 或 Zenodo（已有 S4 reproducibility manifest 锚定，扩展即可），并在 §6.6 引用第三方 registry URL。

### Dimension 4 — Benchmark 公正（baseline SOTA / 指标对己有利 / test-set 独立性）

#### 4.1 §6.6 head-to-head 缺 LLM-assisted MR identification 这一 2025–2026 真正的 SOTA
- **【致命】** §6.6 只与 GenMorph（GP-evolved，Ayerdi 2023）做 head-to-head，未与 Shin 2024 / GPTMR 2025 / AutoMT 2025 / Xu TOSEM 2024 做对比。这四篇是 2024–2026 LLM-assisted MR identification 的 *公认 SOTA*，论文 Related Work（§2.3, line 182）已引但未做实验对比。GenMorph 是 2023 的 GP baseline，2024–2026 的 GP→LLM 范式转移使 GenMorph 不是当前 SOTA。
  - **证据**：line 182（论文承认这些是"Further LLM-assisted variants... extend this template into safety-critical or rule-rich domains"），line 1486 (b)/(d)（Set L、Set M 是 *未来* work），`paper_claims_summary.md` 论点 E "NOT SUPPORTED"。
  - **TOSEM R2 为什么会 catch**：这是 R2 视角下最致命的一击。"对比 SOTA"是 TOSEM 实证投稿的 mandatory 要求；只对比 2023 的 GP baseline 而忽略 2024–2026 的 LLM-assisted SOTA 等于"benchmark cherry-picking 弱对手"。Reviewer 2 会直接写："The authors compare against GP baseline only, while LLM-assisted MR identification (Shin 2024, GPTMR 2025, AutoMT 2025, Xu 2024) constitutes the actual SOTA in this period. The head-to-head is not against the strongest baseline."
  - **建议缓解**：（a）至少把 Set L（GPT-4 prompt-based）扩展为 multi-LLM ensemble baseline（参见 §1.3）；或（b）将 §6.6 重命名为"§6.6 vs GP baseline (GenMorph)"并在 §Threats 与 limitations 中明确声明"head-to-head against LLM-assisted MR identification (Shin 2024, GPTMR 2025, AutoMT 2025) remains as committed future work; the current head-to-head's scope is restricted to GP-evolved baselines"；（c）若时间允许，跑 1–2 LLM-baseline arm 在投稿前补足。

#### 4.2 Pooled McNemar p=0.077（30-min）的方向是 Set G 领先 — abstract 未明示
- **【严重】** `kit_007_handoff.md` §2 报告"§6.6 30-min: Set N 0.516, Set G 0.645, McNemar p=0.077；one-sided p≈0.038"。即在 GenMorph 的 *官方* 30-min budget 下，Set G **方向上领先 13 个百分点，one-sided 已达 α=0.05**。但 §6.6 line 1381–1396 仍报告 1-min 数据为主，30-min 数据未在论文 LaTeX 落地。`paper_claims_summary.md` 论点 E 标记 "NOT SUPPORTED"。
  - **证据**：`kit_007_handoff.md` §2，`e3b_gp_30min_rerun_results.md` line 11–14；论文 line 1383（"GenMorph upstream default 30 min"，"budget asymmetry handicaps Set G in the conservative direction relative to any parity claim"）— 但 30-min 实际数据未在论文中报告，只是承诺"future work"。
  - **TOSEM R2 为什么会 catch**：`kit_007_handoff.md` 已是 *已完成* 数据（commit c9e6636）。论文若不更新，等于 *已知数据未报告* 的 selective-reporting，这是 SE 社区零容忍的诚信红线。CLAUDE.md §1（"诚实优先于救援"）明确禁止此行为。论文当前 §6.6.1 Pooled head-to-head 段落（line 1381–1407）未提及 30-min 数据，仅说"A 30-min GAssert rerun is committed in supplementary §S7-d4j as future work"——但实际数据已完成。
  - **建议缓解**：（强制）投稿前更新 §6.6.1 Pooled head-to-head 段落，将 30-min 数据作为 primary 报告，1-min 数据作为 sensitivity row；删除"30-min rerun is committed as future work"措辞。再不更新就是 *事实-论文 不一致* 的 publication blocker。

#### 4.3 NOETHER 评估指标 coverage_NOETHER 是自评评分
- **【严重】** §6.6.2 Table 4（line 700–708）报告 "Structural coverage (coverage_NOETHER): 1.00 / 0.40 / 0.20"。该指标的分母是 |𝕄(𝒜_equi)| —— *NOETHER 自己定义的* MetaPattern 集合大小。Set N 由 NOETHER 一对一覆盖，coverage 必为 1.00。Set L / Set B 用 NOETHER 的 block 来打分，自然偏低。
  - **证据**：line 712（"H1 is consistent with the data, but by construction"）— 论文已诚实承认；但 contribution C4 / abstract 仍以 "structural-coverage predictions hold across the three instantiations" 作为主结论。
  - **TOSEM R2 为什么会 catch**：自定义指标作为 selling point 是 metric cherry-picking 的标准 R2 catch，特别是当指标的 *构造* 决定了自家方法必然得 1.00。
  - **建议缓解**：将 coverage_NOETHER 从 contribution C4 中移除，仅保留为 *诊断指标*（用于审视 LLM/literature baseline 在 NOETHER block 下的覆盖），不作为 *评价* 指标。Detection rate 才是公平指标。

#### 4.4 §7 (line 994) "$\mathcal{L}^*$-block blindness" prediction 的 falsification threshold（1/3 on more than one SUT）是 ex-ante 还是 ex-post 设定，文中无明确证据
- **【严重】** §7.1 line 1080–1085 声明 "We define 'materially above zero' in advance as a single $L_{\mathrm{scale}}$ MR killing a third or more of its PIT mutants on more than one of the SUTs"。该 1/3 阈值是否 *真的 ex-ante* 设定？论文未引用 git timestamp 锁定该阈值（与 SUT-selection criterion 不同，后者明确引用 commit 6ac3fa3）。当前数据显示 hypotSig=2/4=50% 单一 SUT 超阈值，5/6 SUTs at zero — 恰好通过"more than one"条件。如果阈值是 1/2 或 1/4 或"more than zero"，verdict 会翻转。
  - **证据**：line 1077–1085（threshold 措辞），line 1224–1232（verdict 计算）；论文未为此 threshold 引用任何 commit hash。
  - **TOSEM R2 为什么会 catch**：HARKing（Hypothesizing After Results are Known）的核心标志是 threshold 与 *观察数据* 高度匹配。论文呈现的 1/3 + "more than one" 恰好让 hypotSig=2/4=50% 不构成证伪——R2 会问"如果阈值是 1/4，verdict 会是什么？"
  - **建议缓解**：（a）为 1/3 + "more than one" 阈值提供 git commit timestamp（与 SUT criterion 同等级别的 pre-registration）；或（b）报告 sensitivity analysis：在 threshold ∈ {1/4, 1/3, 1/2} × {more-than-zero, more-than-one, more-than-two} 网格下 verdict 的稳定性。
