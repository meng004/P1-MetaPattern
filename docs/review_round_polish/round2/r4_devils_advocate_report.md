## Devil's Advocate Review

### Strengths acknowledgement (1–2 sentences, mandatory for fairness)

The manuscript is unusually honest about what it does not establish: the negative PWR instantiation (§subsec:negative-pwr) explicitly falsifies the stronger Theorem 1′ on the authors' own primary domain, and §6.6 transparently reports Set N dominated by Set G on D1. Both moves are non-trivial relative to the field's norm and deserve credit.

### Strongest Counter-Argument

The paper's most ambitious claim, taken at face value, is that NOETHER answers the *closure* question for MetaPatterns through Theorem 1. The single strongest counter-argument is that Theorem 1 is **definitionally near-vacuous and the substantive content of the paper is upstream-inductive — that is, NOETHER has not solved the closure problem at all; it has relabelled it**.

Examine the chain: $\mathrm{MR}(\mathcal{A}_P)$ is *defined* (Definition 13, "algebra-induced MR") as exactly the image of the `Translate` map applied to single-block invariants (Definitions 12–13, §3.1, lines 320–344). Theorem 1 (§3.3, line 367) then states that $\mathbb{M}(\mathcal{A}_P)$, produced by CONSTRUCT-MP, is "closed" over $\mathrm{MR}(\mathcal{A}_P)$. The proof (App. C.6.1, lines 2713–2719) is two lines of set-theoretic bookkeeping: it observes that if $\rho = \mathrm{Translate}(\iota, s)$, then by construction $\rho$ ends up in $m_s$ (Step 2 of CONSTRUCT-MP). The authors *acknowledge* this (§3.3, line 383: "A sceptical reading might object that the by-construction status of Theorem 1 makes it near-tautological. We accept this characterisation for the literal content of the theorem"). But the rescue ("substantive value lies elsewhere … structural-adequacy claim") does not relocate the substance — it relocates the burden onto **Hypothesis 1 (eight-block sufficiency)**, which the authors themselves classify as empirical and which is the only place where the eight-block list could be wrong. Theorem 1 is therefore not a closure theorem of the framework; it is the tautology *"$\mathbb{M}(\mathcal{A}_P)$ is closed under the operator we defined $\mathbb{M}(\mathcal{A}_P)$ to be the image of"*. The paper's own Theorem 1′ falsification (§subsec:negative-pwr) **proves this point**: the moment one tests closure against a wider class of MRs (those formulable in $\mathcal{A}_P$ but not necessarily reachable by `Translate`), the result fails on the framework's principal domain. So the testable, non-tautological version of the closure claim is false on PWR. The non-falsifiable version (Theorem 1) is trivially true. There is no closure result with positive content **and** non-trivial scope. The contribution the abstract sells as "algebraic closure under `Translate`" is therefore vocabulary, not theorem; the empirical hard work remains exactly where it always was (the upstream curation of $\mathcal{A}_P$ and its eight blocks), and the field-shaping advance promised by the Noether analogy in §1 (line 114, "replaced an empirically curated catalogue … with a derivation") has not been delivered. The paper's response to this would presumably be "but we explicitly disclose this in the Scope boxes"; the rebuttal is that exhaustive disclosure of a tautology does not convert it into substance.

### Ignored Alternative Explanations / Paths

1. **METRIC+ + 100-sample LLM ensemble would produce equivalent MR coverage at lower cost**. The paper's own Set L data (line 1813: 487 LLM-proposed MRs, 212 matching Set N templates, plus 275 outside the 8-block frame including *associativity, identity/inverse element, monotonicity*) demonstrates that LLM-prompted generation **already covers $> 100\%$ of Set N's reach**. The cost comparison (Table 8) and the time savings (10 h human distillation vs seconds API call) suggest the practical recommendation is "use METRIC+ as scaffold + LLM ensemble at high temperature with diversity rewards" — exactly what the paper's own data supports. This alternative path is not seriously evaluated; instead, Set L is held fixed as a single $n=1$ GPT-4 sample at temperature 0 in §subsec:case-study (line 665) to make a comparison Set N can win.

2. **A "block compactness" diagnostic without the algebra**. The paper's most operationally useful claim — "structural coverage" $\mathrm{coverage}_{\mathrm{NOETHER}}$ as a diagnostic — does not require Theorem 1 to function; a tester could compute "how many of these eight categories did my MR set touch?" without any operator algebra. The Theorem 1 closure proof is not load-bearing for the empirical utility; the eight-block list itself is. So the paper's actual contribution is **the eight-block list (Hypothesis 1)**, not Theorem 1. The honest framing would be "we propose an eight-block taxonomy and demonstrate its applicability on three domains" — much more modest than "constructive framework with closure theorem".

3. **Empirical-symmetry detection (mentioned in §7.7 line 2510) as the upstream automation**. The paper acknowledges this is the genuinely hard problem but commits to none of three sketched directions. A reasonable Devil's-Advocate alternative paper would *start* with the upstream automation problem and treat downstream `Translate` as trivial bookkeeping.

4. **Direct DSL-based MR generation for relational queries**. The query-equivalence literature (Wang2024QED, Zhou2022SPES, cited line 822) already provides SMT-based query-equivalence solvers that handle the four MRs of §subsec:third-domain *and* the AggregateExtractProjectRule (cited as a Theorem 1′ counter-example at line 849). The NOETHER instantiation on $\mathcal{A}_{\mathrm{rel}}$ adds **no operational capability** beyond what these tools already provide; the framework's only contribution is a different vocabulary.

### Missing Stakeholder Perspectives

- **Industrial Java/C++ test engineers (CCF-C or higher conference audience)**: They will read this paper and find it predicates a 10-hour upstream distillation step with mathematical objects they have not seen since undergraduate. The §7.5 engineering guidance (line 2481) gives one rule of thumb ($K$-sweep audit, $\tau \approx 10^2 \epsilon_{\mathrm{fp}}$) but offers no protocol for *deciding whether a program admits $\mathcal{A}_P$* — the question every practitioner would ask first.
- **Reproducibility-via-cross-team-agreement reviewers**: The framework claims reproducibility-via-algorithm: once $\mathcal{A}_P$ is fixed, CONSTRUCT-MP is mechanical. But MR identification's known pain-point (line 116) is not algorithm reproducibility — it is *that two practitioners disagree on which MRs the program admits*. The relevant kind of reproducibility is **inter-rater agreement on $\mathcal{A}_P$ distillation**, which the paper has not measured with any independent humans. The LRCA $\kappa = 0.927$ (line 2359) measures inter-LLM agreement, not inter-human.
- **TOSEM editors looking for theoretical contribution**: Theorem 1's proof is two lines (App. C.6.1, line 2713). Theorem 2's proof is six lines (line 2723). The substantive theorem proofs — the negative-PWR exhaustion (App. C.6.1–C.6.3, lines 2767–2865) — are *falsifications* of the conjecture, not establishments of new positive theorems. A theoretical-track reviewer will count one tautological theorem, one assumption-based complexity bound, and one carefully-proven non-theorem.
- **Empirical-software-engineering reviewers**: The case study is $n=20$ on one EGNN model; the head-to-head is $n=62$ ($n=57$ post-equivalent-mutant exclusion, $n=52$ on D1, $n=5$ on D2) on one Apache Commons Math sub-package; the DeepCrime pilot is $n=5$. Pooled across the paper, the empirical evidence base is **smaller than a typical single ICSE/FSE empirical paper**, and Bonferroni-controlled significance is achieved on **zero** per-SUT contrasts (line 2033).

### Unexamined Premise (Frame-Lock)

**The paper's central unexamined premise is that "MR identification" is the bottleneck and a structural-derivation framework would relieve it.**

The §1 framing (lines 116–124) takes "MR identification" as obviously the binding constraint, citing Segura 2016 and LiTOSEM 2025. But the **economic and engineering reality** of metamorphic testing in practice may be different: it may be that *MR maintenance and reuse* — not initial identification — is the binding constraint. A 2-line MR a tester writes in 5 minutes is rarely the bottleneck; the bottleneck is whether *that MR continues to be valid as the SUT evolves*, whether it can be ported when a new SUT comes online, and whether the tester maintaining the test suite six months later can understand the original author's intent. NOETHER's framework, by emphasising algebra-derivation, **raises the upstream cost** (10 h $\mathcal{A}_P$ distillation per family) while leaving the *maintenance* problem unaddressed. The Noether-analogy (1918, replacing inductive catalogues with derivations) is appropriate to a setting where the number of invariants is large and inductive enumeration is cognitively costly; in MR practice the *invariants per program* are typically $\leq 10$, and inductive enumeration takes minutes.

Equivalently, the framework optimises for the wrong cost component. A practitioner-led survey (e.g. the Segura 2016 and LiTOSEM 2025 surveys the paper cites) would likely identify *MR adequacy assessment*, *MR cost-effectiveness*, and *MR co-evolution with SUT* as more binding constraints than initial MR identification. The paper does not consider that MR identification might **already be cheap enough**, and that algebraic-derivation might therefore be over-engineering for a problem the field has informally adapted to.

A subsidiary unexamined premise: **the "operator-algebra-friendly" precondition selects exactly the SUTs where MR identification is already easiest**. Reactor physics, equivariant ML, and relational queries are all domains where the canonical invariants are known *because the field has had decades to write textbooks about them* (BellGlasstone1970, Bronstein2021GDL, query optimisation). For industrial software where the textbook is missing (CRUD apps, microservices, transaction systems, payment gateways), there is no $\mathcal{A}_P$ to distil; the framework declares these "out of scope by construction" (line 159, "programs lacking such structure are out of scope by construction"). So the framework systematically addresses the **easy MR-identification cases** and disclaims the hard ones — which is exactly the opposite of what a binding-constraint-relief tool should do.

### Observations (Non-Defects)

- The negative-PWR instantiation (§subsec:negative-pwr, App. C.6) is genuinely admirable: the authors picked their *strongest* domain and proved that their *strongest* conjecture fails there.
