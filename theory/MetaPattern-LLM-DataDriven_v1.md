# 元模式引导的GEP蜕变关系识别方法研究：实验方案

## 核心思路

**元模式（MetaPattern）识别输入模式，GEP识别输出模式。** 将MR识别分解为两阶段：第一阶段利用五元模式（守恒性P1、单调性P2、收敛性P3、轨迹性P4、偏序性P5）的推理策略系统生成有物理意义的输入变换；第二阶段利用GEP在程序运行轨迹数据上搜索对应的输出关系符号表达式。二者结合形成"领域知识引导 + 数据驱动发现"的协同框架（MetaPattern-Guided GEP，简称**MPG**）。

---

## 第一部分：问题分析与研究假设

### 1.1 MR识别的核心挑战

当前MR识别面临三重困境：

**挑战C1：输入模式的盲目性。** 现有GEP/PSO等数据驱动方法在高维输入空间中盲目搜索，数据变异算子（INC、DEC、MUL、NEG等）缺乏物理语义。对于反应堆物理程序，输入参数动辄数十个（核素密度、通量、截面、几何参数等），随机组合产生的输入偶对绝大多数无物理意义，导致搜索效率极低。

**挑战C2：输出关系的表达局限。** 已有方法预设输出模式为多项式（Zhang等PSO方法）或预定义的16种函数形式（李萌DDHM方法的线性/二次/S/指数等），无法表达MR的丰富结构——如偏序约束（P2/P5）、路径形态约束（P4：先增后降）、收敛极限约束（P3）。

**挑战C3：识别结果缺乏物理可解释性。** 纯数据驱动方法产出的是似然MR，无法与物理方程性质或数值算法特性建立对应关系，工程师难以判断其检错价值和适用范围。

### 1.2 根本原因

三重困境的根本原因在于：**现有方法将MR识别视为单一的函数逼近问题，忽视了MR的结构先验——即元模式。**

元模式不是"事后分类标签"，而是"事前推理策略"。每个元模式对应一种特定的提问方式：P1问"什么不该变"，P2问"往哪个方向变"，P3问"推到极端会怎样"，P4问"路径长什么形状"，P5问"谁比谁更准"。这些策略可以系统地约束输入变换的生成空间，同时限定输出关系的候选形式，从而将MR识别从"大海捞针"转变为"按图索骥"。

### 1.3 研究假设

**H1（输入模式假设）：** 元模式引导的输入变换比随机数据变异产生的输入偶对更有效——在相同计算预算下，MPG方法发现的MR数量多于纯GEP方法，且非平凡率更高。

**H2（搜索效率假设）：** 元模式对输出关系候选形式的约束可将GEP搜索空间压缩至少一个数量级——体现为GEP收敛代数显著减少、适应度更高。

**H3（物理可解释性假设）：** MPG方法识别的MR中，可归入五元模式并获得物理解释的比例显著高于纯GEP方法。

### 1.4 预期结果

| 指标 | 纯GEP基线 | MPG方法（预期） | 改进幅度 |
|------|----------|-------------|--------|
| 有效MR发现数（固定计算预算） | 3~5条 | 10~15条 | 2~3× |
| 非平凡MR占比 | <20% | >50% | >2.5× |
| GEP平均收敛代数 | >500 | <200 | >2.5× |
| 物理可解释MR占比 | <30% | >80% | >2.7× |
| 变异检测率（Mutation Score） | 40~60% | 70~85% | ~1.5× |

## 第二部分：方案可行性论证

### 2.1 理论可行性

MPG方法的核心机制是**将先验约束注入搜索过程**，这在进化计算领域有坚实的理论基础——约束优化中的可行域缩减定理表明，有效约束可指数级减小搜索空间而不丢失最优解。

具体地，五元模式对GEP的约束方式为：

| 元模式 | 输入变换约束 | 输出关系候选形式约束 | GEP函数集缩减 |
|--------|-----------|----------------|------------|
| P1守恒性 | 置换/翻转/重排类变换 | y₂ = y₁（或y₂ = f(y₁)的恒等函数族） | 仅保留 =, ≈ 运算 |
| P2单调性 | 单参数增/减 | y₂ > y₁ 或 y₂ < y₁ | 仅保留 >, <, ≥, ≤ |
| P3收敛性 | 离散化参数精化 | |y₂ - y_ref| < |y₁ - y_ref| | 保留 |·|, diff, limit |
| P4轨迹性 | 时间/燃耗序列 | 极值/拐点/渐近行为 | 保留 sign(dy/dt), d²y/dt² |
| P5偏序性 | 切换算法/方法 | y_A ⊕ y_B（⊕为可预测的偏序） | 保留 >, <, diff, ratio |

### 2.2 工程可行性

三款PWR开源程序均具备自动化运行条件：

| 程序 | API/脚本接口 | 自动化程度 | 计算成本（单次） |
|------|-----------|----------|-------------|
| SCALE/ORIGEN | SCALE命令行 + TRITON驱动 | 高（批处理脚本） | ~秒级 |
| OpenMC | Python API（完善） | 极高 | ~分钟级（MC统计） |
| OpenMOC | Python API | 高 | ~秒到分钟级 |

**聚焦两个方程**：Bateman燃耗方程和Boltzmann中子输运方程——这是已有57条MR的基础方程，有充分的对照数据。

### 2.3 潜在风险与不足

**R1：GEP表达能力的天花板。** GEP本质是符号回归，擅长发现解析函数关系（如y₂=2y₁+c），但不擅长表达逻辑约束（如"先增后降"的路径形态）。对P4轨迹性和P5偏序性的MR，GEP可能需要扩展为多目标优化或引入逻辑谓词。

**R2：MC程序的统计噪声。** OpenMC的输出带有统计不确定度（σ），GEP拟合时可能将噪声当作信号。需要引入统计显著性检验作为适应度函数的修正项。

**R3：先验约束可能过强。** 如果元模式分类不完备（已知覆盖率~97%但非100%），强约束可能遗漏不属于五元模式的MR（约3%）。需要保留"无约束GEP"作为补充搜索通道。

## 第三部分：实证研究设计

### 3.1 被测程序与目标方程

| 程序 | 目标方程 | 选取理由 |
|------|--------|--------|
| SCALE/ORIGEN | Bateman方程 | 双求解器（CRAM+MATREX），阶数可调，已有26条方程匹配MR作对照 |
| OpenMC | Boltzmann方程（MC） | 开源Python API，支持本征值和固定源模式，已有22条方程匹配MR |
| OpenMOC | Boltzmann方程（MOC） | 确定论方法代表，角度/空间/能群参数可调，已有18条方程匹配MR |

### 3.2 MPG方法的两阶段流程

```
┌─────────────────────────────────────────────────────────┐
│ 阶段一：元模式引导的输入变换生成                             │
│                                                         │
│  输入: 被测程序P, 参数列表Θ, 元模式集M={P1..P5}              │
│  For each θ ∈ Θ:                                        │
│    For each m ∈ M:                                      │
│      If PMCM[θ,m] is applicable:                         │
│        Generate input transform r(θ,m) using             │
│        meta-pattern strategy template                    │
│        → Output: {(x_src, x_fup)} input pairs            │
│                                                         │
│ 阶段二：GEP搜索输出关系                                     │
│                                                         │
│  输入: input pairs, 元模式m的输出形式约束                     │
│  Configure GEP:                                         │
│    Function set ← constrained by m                       │
│    Terminal set ← {y_src, y_fup, constants}               │
│    Fitness ← R²(meta-pattern-specific)                   │
│  Run GEP → candidate output relation R                   │
│  Validate R on hold-out test set                         │
│  If valid: MR = (r, R, m)                               │
└─────────────────────────────────────────────────────────┘
```

### 3.3 聚焦的具体实验

#### 实验1：Bateman方程上的MPG（ORIGEN）

**选取参数（8个）：** 初始核素密度N₀、中子通量φ、燃耗步长Δt、总燃耗时间T、CRAM阶数k、核素数量n、衰变常数λ、截面σ

**元模式×参数矩阵（8×5=40个单元格）：** 逐格分析适用性，对每个适用单元格生成输入变换。

示例输入变换：

| 参数 | P1守恒性 | P2单调性 | P3收敛性 | P4轨迹性 | P5偏序性 |
|------|--------|--------|--------|--------|--------|
| φ | — | φ↑→N_fission↑ | — | N(t;φ)曲线形态 | — |
| Δt | Δt拆分→N不变 | — | Δt→0收敛 | — | — |
| N₀ | αN₀ᴬ+βN₀ᴮ线性叠加 | — | — | — | — |
| k(CRAM阶数) | — | — | k↑→精度↑ | — | CRAM vs MATREX |

**GEP配置：**
- 基因长度：头部h=8，尾部t=9
- 函数集（P1约束）：{=, -, abs, /}（检测y_fup = y_src或y_fup/y_src = 1）
- 函数集（P2约束）：{>, <, -, sign}
- 函数集（P3约束）：{-, abs, /, log}（检测|y_fup - y_ref|递减）
- 种群规模：200，最大代数：500
- 适应度：按元模式定制（见3.4节）

**数据生成：** 每个输入变换生成100组(x_src, x_fup)对，驱动ORIGEN执行，收集关键核素（U-235, Pu-239, Cs-137, Cm-244等15种代表核素）的密度输出。

#### 实验2：Boltzmann方程上的MPG（OpenMC + OpenMOC）

**选取参数（10个）：** 粒子数N_p、能群数G、角度阶数L、空间网格δ、截面Σ_t/Σ_s/νΣ_f、几何尺寸R、边界条件BC、源强S

**元模式×参数矩阵（10×5=50个单元格）。**

示例输入变换：

| 参数 | P1守恒性 | P2单调性 | P3收敛性 |
|------|--------|--------|--------|
| 几何R | 镜面翻转→φ对称 | R↑→k_eff↑ | — |
| Σ_a | — | Σ_a↑→k_eff↓ | — |
| N_p(MC) | — | — | N_p↑→σ↓ |
| 能群G | — | — | G↑→精度↑ |
| BC | — | BC偏序链 | 真空→扩散退化 |

**跨程序P5实验：** 对同一PWR pin-cell问题，OpenMC（MC法）vs OpenMOC（MOC法），比较k_eff。P5预测：MOC在强吸收区（如Gd棒）偏差大于弱吸收区。

### 3.4 元模式定制的GEP适应度函数

| 元模式 | 适应度函数定义 | 说明 |
|--------|-----------|------|
| P1 | $f = 1 - \frac{1}{n}\sum_{i}\frac{|y_i^{fup} - g(y_i^{src})|}{|y_i^{src}|+\epsilon}$ | g为候选恒等/线性变换 |
| P2 | $f = \frac{1}{n}\sum_i \mathbb{1}[\text{sign}(y_i^{fup}-y_i^{src}) = s_{pred}]$ | s_pred为元模式预测方向 |
| P3 | $f = \frac{1}{n}\sum_i \mathbb{1}[|y_i^{fup}-y_{ref}| < |y_i^{src}-y_{ref}|]$ | 检查精化是否改善 |
| P4 | $f = \text{DTW}(y^{actual}, y^{template}) / \text{DTW}_{max}$ | 动态时间规整匹配形态模板 |
| P5 | $f = \frac{1}{n}\sum_i \mathbb{1}[\text{sign}(y_i^A - y_i^B) = s_{pred}]$ | 检查偏序方向 |

### 3.5 评价指标

| 指标 | 定义 | 用途 |
|------|-----|------|
| **MR发现率（MDR）** | 有效MR数 / 计算预算（CPU小时） | 效率 |
| **非平凡率（NTR）** | 非平凡MR数 / 总MR数 | 质量 |
| **召回率（Recall）** | 再发现的已知MR数 / 已知MR总数 | 与人工基准对照 |
| **精确率（Precision）** | 经人工验证为真MR / 算法输出MR | 假阳性率 |
| **变异检测率（MS）** | 被检出的变异体数 / 总变异体数 | 检错能力 |
| **GEP收敛代数** | 达到适应度阈值的平均代数 | 搜索效率 |
| **PMCM覆盖增量** | Adequacy(S_after) - Adequacy(S_before) | 充分性改善 |

## 第四部分：预期结果分析与讨论

### 4.1 预期结果

#### 实验1预期结果（ORIGEN/Bateman方程）

已知ORIGEN有26条方程匹配MR。MPG方法预期：

- P1单元格（4个适用）：再发现Bur-Phy-01（步长拆分不变性）、Bur-Phy-03（初始条件线性叠加）→ 召回率≥50%
- P2单元格（5个适用）：再发现Bur-Phy-02（变通量步长敏感）、Bur-App-01~04的单调性MR → 预期大部分为平凡MR
- P5单元格（1个适用）：CRAM vs MATREX偏差定位 → 需要跨求解器运行，GEP检测偏差模式
- 新发现MR：预期在P3×σ（截面→收敛行为）和P4×N₀（初始密度→轨迹形态）中发现1~3条新MR

**纯GEP基线预期：** 在相同计算预算下，仅能发现3~5条以多项式关系表达的MR，大部分为P2平凡单调性（如"φ↑→N_fission产物↑"），且无法发现P1/P5类型MR。

#### 实验2预期结果（OpenMC+OpenMOC/Boltzmann方程）

- P1：再发现Bol-Phy-02（几何镜面翻转不变性）、Bol-Phy-04（源强倍增）
- P2：再发现Bol-Phy-11（吸收截面增大→k降）等平凡MR
- P3：在OpenMOC上发现Bol-Alg-01~03（角度/空间/能群收敛），GEP拟合收敛速率
- P5：OpenMC vs OpenMOC在含Gd pin-cell上的偏差方向和分布

### 4.2 讨论框架

**D1：元模式引导的定量增益分析。** 比较MPG与纯GEP在MR发现率曲线上的差异，分析增益来源——是输入空间缩减（搜索效率提升）还是适应度函数约束（解质量提升），或二者兼有。

**D2：非平凡MR的发现机制。** 分析MPG新发现的MR是否属于P5偏序性或P1守恒性——这两类元模式的非平凡率最高（56%和50%），且纯GEP几乎无法发现。

**D3：GEP的表达能力边界。** 记录MPG方法中GEP无法表达的MR类型（预期集中在P4轨迹性的非单调形态和P5的精度偏序），分析原因并提出后续扩展方向。

**D4：跨程序MR的一致性。** 对同一物理方程的MR在三个程序上的验证结果进行交叉分析——如果某条MR在ORIGEN上成立但在Serpent上不成立，可能揭示算法实现差异。

**D5：与PMCM充分性框架的耦合。** 计算MPG识别前后的Adequacy值变化，验证MPG是否系统性地填补了PMCM矩阵的空白单元格。

## 第六部分：第一轮专家评审

### 评审身份：蜕变测试领域资深专家

**致命问题1：金标准的循环论证风险（Circular Validation）**

MPG方法使用"人工识别的84条MR"作为金标准计算召回率，但这84条MR本身就是用元模式框架识别的。如果MPG方法使用相同的元模式作为输入，再去"再发现"这些MR，这不是验证方法有效性，而是验证"用相同假设能得到相同结论"。召回率指标存在严重的循环论证：**你用P1策略生成输入变换，然后GEP搜索到一个恒等关系，你声称"再发现了Bur-Phy-01"——但这条MR本身就是P1策略的直接产物。** 这不证明GEP有效，只证明P1策略生成了正确的输入变换。

**致命问题2：GEP对非数值MR的根本无能（Expressiveness Gap）**

84条MR中，约40%（P2的偏序、P4的路径形态、P5的算法偏序）不是函数关系而是逻辑/拓扑约束。GEP是符号回归工具，只能发现y₂=f(y₁)形式的关系。你无法用GEP表达"Cm-244的偏差应大于U-235的偏差"（P5偏序性Bur-Alg-04），也无法表达"238Pu密度先增后降"（P4轨迹性Bur-App-06）。**用GEP覆盖全部五个元模式是虚假承诺——它最多覆盖P1和P3中的解析关系子集。** 将P2/P4/P5的适应度函数改为分类准确率不是"扩展GEP"，而是将GEP降级为一个分类器——但GEP的优势恰恰在于符号表达式发现，不在分类。

**致命问题3：缺乏真正的外部验证（No External Ground Truth）**

所有评价指标都是自我参照的：召回率参照自己的MR库，精确率由同一团队的专家判定，变异检测率的变异体设计也基于同一方程分析。没有独立第三方的MR集合作为外部验证。**如果这84条MR本身就有遗漏或错误，整个评价体系就建立在错误的基础上。** 在核工程领域，至少应该用SCALE/ORIGEN的开发者自测用例或OECD/NEA基准题作为外部参照。

## 第七部分：第一轮修改

### 修改M1：消除循环论证——引入"盲区MR"评价

不再将84条已知MR的召回率作为主要指标。改为：

**核心评价方案：** 将84条MR分为训练集（60%=50条）和测试集（40%=34条）。训练集的元模式标签对MPG方法可见（用于构建PMCM矩阵和元模式策略），但测试集的MR标签完全隐藏——MPG方法必须"盲目地"再发现它们。

**新增"发现新MR"指标：** MPG方法识别出的、不在84条已知MR中的新MR，由独立的反应堆物理专家（非本团队成员）进行盲审判定是否为真MR。

### 修改M2：GEP能力边界的诚实声明——分层方法设计

承认GEP只适用于函数/解析关系形式的MR，将方法框架从"MPG统一方法"修改为"MPG分层方法"：

- **Layer 1（GEP适用层）：** P1守恒性中的恒等/线性叠加关系、P3收敛性中的精化速率关系 → 使用GEP搜索符号表达式
- **Layer 2（统计检验层）：** P2单调性、P5偏序性 → 不使用GEP，改用Wilcoxon秩和检验/符号检验自动判定方向
- **Layer 3（模板匹配层）：** P4轨迹性 → 不使用GEP，改用DTW（动态时间规整）匹配预定义形态模板（单调增、单调减、先增后降、先降后增、S形、平衡态6种）

**评价指标相应调整：** GEP收敛代数仅在Layer 1上报告，Layer 2/3使用各自的统计功效和模板匹配准确率。

### 修改M3：引入外部验证基准

**外部基准1（OECD/NEA基准题）：** 使用OECD/NEA燃耗基准题（如Phase-IIB）的参考结果作为外部oracle，验证MPG发现的MR在独立计算条件下是否成立。

**外部基准2（Serpent作为独立参照程序）：** 在OpenMC上发现的MR，使用Serpent 2独立验证——因为Serpent使用相同的物理方程但完全不同的代码实现。MR在两个独立程序上都成立才算"真MR"。

**外部基准3（公开发表的MR）：** 使用Segura等(2016 TSE)和Li等(2025 TOSEM)综述中公开发表的数值计算领域MR作为跨领域验证集。

## 第八部分：第二轮专家评审

### 评审身份：蜕变测试领域资深专家

**严重问题1（非致命）：Layer 2/3不是MR"识别"而是MR"验证"**

修改后的分层方法中，Layer 2（统计检验）和Layer 3（模板匹配）实际上是在**验证**元模式策略模板生成的候选MR是否在数据上成立。这不是"识别"新MR——输入变换和输出关系的结构都是元模式模板预先给定的，统计检验只是在确认它们。论文如果声称"MPG方法识别了N条MR"，而其中70%来自Layer 2/3的模板验证，会被审稿人质疑"你到底识别了什么新东西"。

**严重问题2（非致命）：训练-测试集划分不够严格**

50条训练集MR的元模式标签可见→构建PMCM→指导搜索。但如果训练集中P5偏序性MR有4条、测试集中P5偏序性MR有1条，那么MPG在测试集上"再发现"P5-MR时，本质上是因为训练集已经告诉它"P5在这个参数上适用"——信息泄露仍然存在。

**严重问题3（非致命）：Serpent外部验证存在共线性**

Serpent和OpenMC都使用MC方法，物理模型高度共线。"MR在两个MC程序上都成立"不能排除"MR只是MC方法的数值特征而非物理真理"。真正的外部验证应该使用确定论程序（如CASMO-5或DRAGON），但这些是商业软件，无法获取。

## 第九部分：第二轮修改

### 修改M4：明确区分"MR识别"与"MR验证"的贡献声明

将论文贡献重新表述为：

- **贡献1（方法论）：** 提出元模式引导的MR识别框架，其中Layer 1是真正的"识别"（GEP发现未知的符号表达式），Layer 2/3是"系统化验证"（自动验证元模式模板生成的候选MR）
- **贡献2（工具）：** MPG框架的工程价值不在于"发现人类不知道的MR"，而在于**自动化和规模化**——将人工专家数周的MR识别工作压缩为数小时的自动化流程
- **贡献3（充分性）：** MPG的PMCM覆盖增量指标证明它能系统性地填补MR集合的结构性盲区

### 修改M5：消除信息泄露——改用Leave-One-Meta-Pattern-Out交叉验证

不再使用随机划分训练/测试集。改为**Leave-One-Meta-Pattern-Out（LOMPO）**：

- 轮次1：隐藏所有P1-MR，用P2~P5训练PMCM，测试MPG能否在P1维度上发现MR
- 轮次2：隐藏所有P2-MR，用P1/P3/P4/P5训练，测试P2发现能力
- ...依此类推共5轮

这消除了元模式层面的信息泄露：MPG必须在**完全未见过某种元模式的MR的情况下**，仅靠该元模式的推理策略模板去发现MR。

### 修改M6：补充MC-确定论跨方法验证

在现有OpenMC(MC) vs OpenMOC(MOC)对比的基础上，增加：

- **ORIGEN(CRAM) vs OpenMC(耦合燃耗模式)：** 同一燃耗问题，确定论CRAM vs MC耦合燃耗，验证Bateman方程MR的跨方法一致性
- **OpenMOC(确定论MOC) vs OpenMC(MC)：** 对同一pin-cell问题，确定论 vs 随机方法，验证Boltzmann方程MR的跨方法一致性
- 如果MR在MC和确定论方法上都成立，排除"仅为MC数值伪影"的可能

## 第十部分：第三轮专家评审

### 评审身份：蜕变测试领域资深专家

**中等问题1：LOMPO验证的统计功效不足**

五轮交叉验证每轮只有一个元模式的MR被隐藏，样本量过小（P5仅9条MR，隐藏后只有9条测试MR，但P4仅10条）。统计功效（power）可能不足以得出显著性结论。建议补充Bootstrap置信区间。

**中等问题2：GEP的可重复性问题**

GEP是随机算法，不同随机种子可能产生完全不同的符号表达式。30次重复是否足够？建议报告跨重复的MR一致性（Jaccard系数）：如果30次运行中某条MR只被发现1次，它的可信度远低于被发现25次的MR。

**中等问题3：计算预算的公平性**

与SOTA方法对比时，应控制相同的计算预算（CPU小时而非"代数"）。GEP每代的计算成本远高于PSO每次迭代（因为GEP需要解码表达式树并评估），所以"GEP收敛代数更少"不等于"GEP更快"。

## 第十一部分：第三轮修改（最终版）

### 修改M7：统计增强

- 对LOMPO的每轮结果补充Bootstrap 95%置信区间（B=1000次重采样）
- 对小样本元模式（P4/P5，≤10条MR），额外使用Fisher精确检验替代χ²检验

### 修改M8：GEP可重复性报告

- 30次重复中引入"MR发现频率"指标：freq(MR_i) = 发现次数/30
- 仅将freq≥0.5（即至少15次被发现）的MR计入"有效发现"
- 报告跨重复的Jaccard一致性系数

### 修改M9：统一计算预算

- 所有方法对比使用统一的计算预算：**1000 CPU小时/方程/程序**
- 各方法在此预算内的MR发现数作为主要效率指标
- 同时报告挂钟时间（wall time）和程序调用次数

## 最终实验方案总结

### 方法：MPG（MetaPattern-Guided GEP）分层框架

| 层 | 适用元模式 | 技术 | 输出 |
|----|----------|------|------|
| Layer 1 | P1守恒性、P3收敛性 | 元模式约束GEP符号回归 | 符号表达式MR |
| Layer 2 | P2单调性、P5偏序性 | 元模式模板 + Wilcoxon检验 | 方向性/偏序MR |
| Layer 3 | P4轨迹性 | 元模式模板 + DTW匹配 | 形态MR |

### 被测系统：3程序×2方程

| 程序 | 方程 | Layer 1 MR | Layer 2 MR | Layer 3 MR |
|------|------|-----------|-----------|-----------|
