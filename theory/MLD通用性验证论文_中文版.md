# 元模式引导的蜕变关系识别：一种具备通用性的LLM辅助输入生成与多策略输出发现框架

---

## 摘要

蜕变关系（MR）识别仍然是蜕变测试的关键瓶颈。现有自动化方法——MR-Scout（基于测试用例驱动的推断）、GenMorph（遗传搜索）和MARS（迭代精化）——各自解决了问题的部分方面，但均缺乏面向系统性覆盖的结构化引导。本文提出MLD（元模式-LLM-数据驱动）三阶段框架，将MR识别分解为：（1）程序语义理解；（2）元模式策略引导的LLM辅助候选输入变换生成；（3）按元模式类型分流的多技术输出关系发现。为验证该框架在元模式分类体系原始开发领域（核工程）之外的通用性，本文在MR-Scout、GenMorph和MARS所使用的基准程序上评估MLD——涵盖数值计算库、数据结构、搜索引擎和机器学习分类器等多个领域。在{占位符：N}个被测程序上，MLD的MR识别精确率达到{占位符：X%}，召回率达到{占位符：Y%}，变异检测率达到{占位符：Z%}，优于{占位符：最优基线}达{占位符：差距幅度}，同时提供了现有方法均不具备的结构多样性保障。

## 1 引言

### 1.1 问题陈述

MR识别是蜕变测试公认的瓶颈。自Chen等人（1998）开创性工作以来的二十余年间，该领域仍然缺乏能够同时实现三个目标的方法：（a）高召回率——发现给定程序的大多数有效MR；（b）低误报率——避免浪费测试预算的虚假关系；（c）结构多样性——确保MR集合覆盖本质不同的属性类型，而非同一模式的冗余变体。

近年来涌现的三种代表性自动化方法——MR-Scout（ICSE 2024）、GenMorph（ASE 2023）和MARS（ISSTA 2024）——各有独特优势但共享同一局限：它们均未提供评估或保障已识别MR集合结构多样性的机制。

### 1.2 元模式假设

我们在反应堆物理软件上的前序工作识别了五个元模式——守恒性（P1）、单调性（P2）、收敛性（P3）、轨迹性（P4）和偏序性（P5）——它们共同覆盖了跨30+应用领域的400+条MR中的97%。本文检验一个大胆的通用性假设：这五个元模式，虽源自数学物理方程，但能够作为通用软件MR识别的结构先验——即使被测程序不存在控制方程。

### 1.3 研究问题

**RQ1（有效性）：** MLD在MR-Scout、GenMorph和MARS各自的基准程序上，能否识别出更多有效且非冗余的MR？

**RQ2（结构多样性）：** 元模式引导是否产生具有更高结构多样性（以PMCM充分性度量衡量）的MR集合？

**RQ3（缺陷检测）：** MLD识别的MR是否比基线方法识别的MR取得更高的变异检测率？

**RQ4（通用性）：** MLD的元模式分类体系能否有效迁移到不具备显式数学模型的领域（如数据结构、搜索引擎、分类器）？

### 1.4 贡献

1. **MLD框架**：一种融合元模式结构先验、LLM语义推理和多技术输出发现的三阶段MR识别方法。
2. **跨领域通用性证据**：首次在非科学计算基准上对五元模式分类体系进行实证评估。
3. **正面对比**：在统一评价指标下，与MR-Scout、GenMorph和MARS在其各自基准程序上进行受控实验。
4. **结构多样性度量**：将PMCM充分性作为MR识别方法的新评价维度。

### 2.2 自动化MR识别：当前最优方法

#### 2.2.1 MR-Scout（ICSE 2024）

**底层机制：** MR-Scout从已有测试用例集中挖掘MR候选。通过对测试代码的静态分析，提取测试用例对之间的输入变换模式和输出断言模式，然后将观察到的具体模式泛化为抽象MR。

**核心技术路径：** 测试代码静态分析 → 输入-输出变换模式提取 → 模式抽象泛化。

**优势：**
- 零领域知识需求——仅从已有测试代码工作
- 在测试充分的程序上精确率高（已有测试编码了开发者意图）
- 直接产出可执行MR

**不足：**
- 召回率受已有测试集质量约束——测试稀疏时发现极少
- 无法发现开发者未隐式测试的MR类型
- 无结构多样性保障——倾向产生同类型MR（主要P1/P2）
- 对无已有测试集的程序不适用

**擅长的元模式：** 主要P1（从等价测试输入中提取不变性）和P2（从边界测试中提取单调性）。极少发现P3–P5。

**适用范围：** 已有丰富单元测试的成熟开源库（如Apache Commons系列、Guava）。

#### 2.2.2 GenMorph（ASE 2023）

**底层机制：** GenMorph使用遗传编程进化MR候选。协同进化输入变换和输出断言，以变异测试反馈作为适应度函数。

**核心技术路径：** 遗传编程 → (输入变换, 输出断言)对的协同进化 → 适应度 = 变异得分。

**优势：**
- 完全自动化——不需要领域知识和已有测试
- 变异得分驱动的适应度直接优化缺陷检测能力
- 理论上可发现任意复杂MR

**不足：**
- 计算成本极高——每代需数千次程序执行
- 产出的MR语法复杂、物理不可解释（"不透明MR"）
- 高假阳性率——进化出的MR可能是数据巧合
- 无结构多样性压力——进化收敛于一种主导MR"物种"（通常是简单的P2单调性，因其变异杀伤信号最强）

**擅长的元模式：** 原则上可发现任何模式，但实践中收敛于P2类（单调性）和简单P1类（等价性）。

**适用范围：** 输入输出关系简单、执行速度快的小型程序（函数级或方法级）。

#### 2.2.3 MARS（ISSTA 2024）

**底层机制：** MARS使用LLM迭代精化生成MR。先提示LLM生成候选MR，然后对程序执行验证，将失败用例反馈给LLM进行精化。

**核心技术路径：** LLM生成 → 执行验证 → 失败反馈 → LLM精化循环。

**优势：**
- 利用LLM世界知识进行领域感知MR生成
- 迭代精化逐步降低假阳性
- 产出自然语言描述的MR，附带解释

**不足：**
- LLM幻觉风险——初始候选常常物理无效
- 精化循环可能收敛于局部最优（反复精化同一MR类型）
- 无系统性覆盖保障——依赖LLM的随意探索
- 对提示词工程敏感——不同提示产出差异极大的MR集合

**擅长的元模式：** LLM世界知识自然生成P1和P2型MR；偶尔P3（收敛性）。极少发现P4（轨迹性）或P5（偏序性），除非显式引导。

**适用范围：** 有丰富文档或广泛知名的软件系统（如标准库、Web框架）。

### 2.3 三种方法的底层机制对比

| 维度 | MR-Scout | GenMorph | MARS |
|------|----------|----------|------|
| **信息源** | 已有测试代码中的隐式知识 | 程序执行的输入-输出轨迹 | LLM的参数化世界知识 |
| **搜索策略** | 模式匹配（确定性） | 进化搜索（随机性） | 提示-响应循环（半随机） |
| **输入变换来源** | 从测试用例对中抽取 | 随机进化 | LLM自由生成 |
| **输出关系来源** | 从测试断言中抽取 | 协同进化的断言 | LLM生成+执行验证 |
| **先验结构** | 无（依赖测试质量） | 无（依赖适应度景观） | 弱（LLM的隐式知识） |
| **停止条件** | 测试集耗尽 | 预算耗尽 | 精化收敛 |
| **根本局限** | 不可能超越已有测试的覆盖范围 | 进化收敛偏倚削弱多样性 | LLM的非结构化探索缺乏系统性 |

**MLD的差异化定位：** MLD引入的元模式是一个**显式结构先验**，它不替代上述三种方法的任何组件，而是提供一个"搜索地图"——告诉搜索过程"应该在MR空间的哪个区域寻找"，并通过PMCM充分性度量量化"还剩哪些区域未被覆盖"。

## 3 MLD框架

### 3.1 总体概述

```
阶段0：程序语义理解
  输入：API文档、源代码、已有测试（如有）
  工具：LLM程序分析
  输出：程序语义描述SemDesc(P)，初始PMCM₀矩阵

阶段1：元模式引导的LLM输入变换生成
  输入：SemDesc(P)，PMCM₀中的空白单元格，元模式策略模板
  工具：LLM结构化推理
  输出：候选MR集合 CandMR = {(r, R̂, m)}

阶段2：多技术输出关系发现
  P1/P3（解析关系）→ GEP符号回归
  P2/P5（方向性/偏序）→ 统计假设检验
  P4（轨迹性）→ 时序形态分析
  P1/P5（结构性约束）→ 约束逻辑验证
  输出：已验证MR集合

阶段3：PMCM充分性评估与迭代
  若Adequacy < 阈值 → 对剩余空白单元格重复阶段1-2
```

### 4.4 评价指标

#### 4.4.1 MR质量指标

| 指标 | 定义 | 用途 |
|------|------|------|
| **精确率（P）** | 有效MR数 / 总输出候选MR数 | 误报控制 |
| **召回率（R）** | 发现的有效MR数 / 金标准中的有效MR总数 | 完整性 |
| **F1** | 2PR/(P+R) | 平衡度量 |
| **非平凡率（NTR）** | 非平凡MR数 / 有效MR数 | 超越显而易见属性的深度 |

**金标准构建方法：** 对每个被测程序，金标准MR集合为以下来源的并集：（a）原始基准论文中发表的MR；（b）所有方法识别的MR合并后，由两名独立标注者人工验证（报告Cohen's κ）；（c）Segura等（2016）综述中重叠领域的MR。

#### 4.4.2 误报分析指标

| 误报类型 | 定义 | 度量方式 |
|---------|------|---------|
| I类误报（无效MR） | MR在正确程序上被违反 | 在未变异程序上执行，计数违反次数 |
| II类误报（平凡MR） | MR有效但不检测任何变异体 | 该MR的变异检测率 = 0 |
| III类误报（冗余MR） | MR有效但被另一条MR完全包含 | 包含性分析：kills(MR_i) ⊆ kills(MR_j) |

#### 4.4.3 缺陷检测指标

| 指标 | 定义 | 用途 |
|------|------|------|
| **变异检测率（MS）** | 被杀变异体数 / （总变异体数 − 等价变异体数） | 总体缺陷检测能力 |
| **唯一杀伤数** | 仅被本方法MR杀伤的变异体数 | 互补价值 |
| **成本效益** | 杀伤变异体数 / CPU小时数 | 经济效率 |

**变异框架：** PIT（Java）或μJava，标准变异算子（AOR、ROR、LCR、UOI、ABS）。每个被测程序生成≥200个变异体；通过人工检查或TCE排除等价变异体。

#### 4.4.4 结构多样性指标

| 指标 | 公式 | 解释 |
|------|------|------|
| **PMCM充分性** | 已覆盖(θ, m)单元格数 / 适用单元格总数 | 结构覆盖完整性 |
| **Shannon熵** | H = −Σ p_m log₂ p_m | 元模式分布均匀性 |
| **Simpson多样性指数** | 1 − Σ p_m² | 随机抽取两条MR属不同类型的概率 |
| **冗余比** | 同一(θ, m)单元格内的MR对数 / 总对数 | 单元格内冗余度 |

#### 4.4.5 效率指标

| 指标 | 定义 | 用途 |
|------|------|------|
| **挂钟时间** | MR识别总耗时 | 实际效率 |
| **程序调用次数** | 被测程序执行次数 | 计算成本 |
| **LLM API调用次数** | LLM查询次数（仅LLM类方法） | API成本 |

### 4.5 公平性控制

- **计算预算统一：** 所有方法在每个被测程序上获得相同的CPU小时预算。对GenMorph（CPU密集型）和MLD（LLM+执行），在相同硬件上以挂钟时间度量。
- **LLM公平性：** MLD和MARS均使用GPT-4o，温度参数（0.7）和max_tokens设置相同。"随机LLM"消融实验使用相同LLM但不含元模式提示，隔离结构化引导的贡献。
- **金标准公平性：** 金标准为所有方法输出（验证后）的并集，不偏向任何单一方法的MR风格。
- **随机性控制：** 对随机方法（GenMorph、MLD、MARS）重复5次，报告均值±标准差。

### 4.6 元模式标注协议

对任何方法识别的每条MR，两名标注者独立将其归入一个元模式（P1–P5或"无"）。以Cohen's κ度量标注者间一致性。分歧由第三名标注者裁决。此协议支撑RQ4的回答（五元模式是否覆盖非科学计算领域的MR）。

## 6 讨论

### 6.1 元模式引导为何有效？

{占位符：基于消融实验（MLD vs 随机LLM）和多样性差距（Adequacy差异）的分析}

**预期分析方向：** 元模式将搜索空间从"生成任意MR"压缩为"为参数θ生成P_m类型的MR"。这类似于METRIC+使用输入域划分引导测试用例生成——但元模式划分的是*MR结构空间*而非输入值空间。消融实验MLD−元模式精确隔离了这一效应。

### 6.2 领域迁移分析

{占位符：逐领域讨论}

**预期发现：**
- **数值计算库（Commons Math）：** 近乎完美迁移。P1（sin/cos的对称性）、P2（sqrt的单调性）、P3（精度收敛）、P5（算法对比）均直接适用。
- **集合库（Guava）：** P1（集合的插入顺序无关性）、P2（大小单调性）强。P3/P4/P5较弱——集合库缺乏"收敛"或"轨迹"的类比，除非考虑迭代器。
- **机器学习（Weka）：** P1（特征置换不变性）、P2（训练数据单调性）已有文献支撑。P4（学习曲线形态）是新颖且可能高价值的应用方向。
- **搜索引擎（Lucene）：** P1（查询词顺序）、P2（增加约束→结果减少）直接对应Segura等的经典搜索引擎MR。P5（不同分析器间的排序质量偏序）是新颖应用。

### 6.3 互补性分析

{占位符：Venn图解读}

**预期发现：** MLD与基线方法高度互补。MLD独特贡献P3/P4/P5类MR——这些是基线方法均未发现的。基线方法可能独特贡献某些MLD的元模式模板未优先考虑的程序特定MR。MLD ∪ 最优基线 的组合应取得最高变异检测率。

**实践启示：** 最优策略可能是MLD ∪ {最优基线}而非单独使用MLD。

### 6.4 五元模式在通用软件上的局限

{占位符：对标注为"无"的MR的分析}

**预期需要研究的新模式：**
- **幂等性**（f(f(x)) = f(x)）：与P1相关但本质不同——P1要求*不同*输入，幂等性重复施加*相同*操作
- **交换性**（f∘g = g∘f）：一种复合属性，不被任何单一元模式捕获
- **崩溃一致性**：程序在任何合法输入上不应崩溃——这是安全属性，非关系属性

### 6.5 效度威胁

**内部效度：** 金标准取并集的方法可能对输出量大的方法过度计数MR。通过去重和标注者验证缓解。LLM的非确定性通过5次重复缓解。

**外部效度：** 仅限Java程序；对动态类型语言的迁移尚不确定。元模式分类体系源自物理学；面向通用软件的重新解释是近似的。

**构念效度：** 变异检测率作为真实缺陷检测的代理指标是成熟但不完美的。PMCM充分性是新度量，其与缺陷检测的相关性尚属假设、未经独立验证。
